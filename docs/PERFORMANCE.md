# 砚页 Windows 本地端性能与验收

## 决策与适用范围

磁盘文件和离线创建的工作区文稿共用输入延迟、滚动和恢复指标。磁盘文件另测原格式解码、保存与外部应用重开。工作区文稿另测本地事务提交、跨页引用、索引和视图更新。多人光标的传输、服务器延迟与远端可用性留到在线阶段。

下文预算是下一阶段拟采用的产品验收值。已有的 0.3.0 观察值列在文末。功能实现、性能达标、格式往返正确三项分别记录。

## 基准机与统计

- **基础机**使用 Windows 11 x64、4 个物理核心、8 GiB 内存、集成显卡、SSD、60 Hz 屏幕，1920 × 1080、125% 缩放、接电平衡模式。**常规机**使用同类配置和 16 GiB 内存。将实际 CPU、磁盘型号、系统构建、驱动、显示缩放、防病毒状态、构建提交写入结果。基础机负责发布验收，常规机帮助定位差异。
- 测正式打包的 x64 版本，使用隔离的用户目录、固定本地样本、无网络。记录第三方软件的版本；互操作检查与性能采样分开执行。使用一致的种子生成样本并记录 SHA-256，读写样本的工作副本。
- **冷启动**为系统重启并空闲后第一次拉起程序，已有同一份基准工作区；**暖启动**为正常退出进程后 60 秒内再次拉起，保留系统页缓存。全新用户目录的首次初始化、版本迁移单列。文档冷开指编辑器尚未载入且文档未在进程内缓存，热切换指目标标签已载入。
- 样本按设备、冷热、规模和模块分别统计。启动目标每组 20 次独立运行；文档打开、重算、搜索、保存各取 30 次；输入、切换、拖动每类至少 200 次。记录 P50、P95、最大值、错误数与超时数。P95 取升序中第 ⌈0.95 × N⌉ 个样本。超时计入失败，不从报表中剔除。

## 通用发布预算

| 场景 | 计时口径与拟定门槛 |
| --- | --- |
| 启动 | 从启动进程到文件中心首屏绘制完成且“打开文件”能响应。基础机冷启动 P95 ≤ 3 s，暖启动 ≤ 1.5 s。首屏操作不等待索引、模板缩略图或非活动编辑器。 |
| 输入 | 从按键或 IME 提交事件到首个呈现正确字符的帧。普通中文输入、拼音组合态提交、退格与撤销分别测；典型样本 P95 ≤ 50 ms。连续输入 60 秒应保持顺序和光标位置。 |
| 滚动与拖动 | 匀速滚动 20 秒并重复 5 轮。60 Hz 下帧间隔 P95 ≤ 20 ms，超过 33.3 ms 的帧占比 ≤ 2%；连续超过 100 ms 的停顿单列。渲染器内用帧回调初筛，实际呈现时间用 Chromium/Windows trace 复核。 |
| 切换与搜索 | 已载入标签切换到可输入 P95 ≤ 150 ms。1 万篇文稿、10 万条块或记录、索引已建，提交关键词到首批正确结果 P95 ≤ 300 ms。中文单字、词组、英文与文件名分别测；新建或编辑内容应在 2 s 内可搜。首次建索引单独计时。 |
| 自动保存与手动保存 | 对工作区普通编辑，从最后一次操作到本地持久事务确认 P95 ≤ 1 s。对典型 Office 文件，从 Ctrl+S 到写入确认 P95 ≤ 2 s，包含源文件变更检查、备份与最终替换。超过 150 ms 的操作应给出进行中状态。 |
| 内存 | 整个应用进程树的 Windows 私有字节数之和。空闲文件中心稳定值 ≤ 350 MiB，单一典型编辑器 ≤ 650 MiB，五类典型文稿标签并存 ≤ 1.2 GiB。连续开关同一组标签 30 次，最后静置 30 s，稳定值相对预热后同状态增加 ≤ 100 MiB。另报打开、导出时的峰值。 |
| 并行任务与恢复 | 一份典型文档持续输入，同时为另一文档建索引、生成缩略图或导出，输入 P95 ≤ 80 ms。触发取消后 250 ms 内显示反馈；任务到达可中断点后释放句柄及临时文件。应用崩溃后重开需恢复已确认的最近修订。 |

输入计时以文档内容实际变化为准，另记异步排版收敛。文档“可编辑首屏”必须能在当前光标处输入、撤销、选择对象，且相关内容和选择映射正确。大文件的首屏和全文件处理完成各有独立计时点。渲染器记录输入事件、绘制与可交互时刻，后台记录解析、索引、提交及导出，以请求 ID 串联。跨进程端到端结果用同一测试驱动的单调时钟计时。

| --- | --- | --- |
| DOCX／工作区电子文档，30 页、3 万汉字、10 张表、5 张图，源文件 ≤ 5 MiB | DOCX 冷开到可编辑首屏 ≤ 2 s；工作区文档首屏 ≤ 800 ms；编辑局部段落应满足输入预算 | 核对图片数、段落样式、表格和显式分页。以 200 页样本观测首次可编辑和末页排版完成两个时刻。 |

| PDF，100 页混排文字、矢量与图片，≤ 20 MiB | 首张清晰可读 ≤ 1.5 s；跳到未缓存目标页并可读 ≤ 500 ms。图像扫描件另组 | 校验页数、旋转、裁切、文字选区；若本期交付批注，保存重开逐条核对坐标和内容。500 页扫描件记录纹理缓存峰值。 |

| 工作区流程图与白板，1,000 节点、1,500 连线，桌面视口内 ≤ 120 节点 | 图纸可选中对象 ≤ 1.5 s；拖动节点到相邻连线更新 P95 ≤ 50 ms；平移缩放满足帧预算 | 检查移动、撤销、保存重开后的节点 ID 与端点引用；5,000 节点测试视口裁剪、命中测试和简化绘制。 |

## 超预算时的处理顺序

1. **先确认耗时发生的位置。** 将启动分解为主进程、索引／元数据、工作区首屏和活动编辑器。把打开分解为读盘、解码、建模、布局、首帧。对长输入追踪单次编辑触发的序列化字节数、IPC 次数、重排块数及后台队列长度。
2. **为交互留出时间。** 当前输入和活动文档优先。解压、全局索引、格式转换和全表重计算由后台任务分批执行，向界面发送可用范围和增量结果。过期任务按文档修订号丢弃；阻塞渲染器超过 50 ms 的任务需要归因。
3. **控制内存与显示成本。** 表格按可见行列绘制，PDF 和幻灯片按页缓存，流程图按可视区域绘制，非活动标签先回收视图缓存。超大输入可先提供分页预览、只读打开或取消，显示实际支持范围。保留下次可恢复的编辑记录。
4. **将正确性放在上线门槛内。** 每轮实测包含修改、保存、关闭、重新打开及语义核对；原格式文件另做第三方阅读器回读。覆盖前源文件摘要变化应提示冲突，另存后原件保持完整。注入满盘、只读目录、异常退出和迁移中断，校验已确认修订可恢复、原件或备份可取回。格式有损、漏字、串行、错算、图形错连或丢失已确认写入均判失败。

同一构建的门槛与上次已验收构建的回归要同时检查。若关键指标 P95 较对照劣化超过 15%，在同机交错重复两组并保存 trace，确认原因后再决定是否放行。原始样本、失败次数、内存峰值、语义检查结果应一同归档。后台采样默认只记计数、尺寸、阶段和耗时。

## 0.3.0 实测起点

2026-11-26，在 Windows 11 专业版 Build 26300、i7-1165G7（4 核 8 线程）、15.8 GiB 内存、SSD 上，运行仓库提交 `7361013` 对应的 Windows x64 便携版和模型代码。运行环境使用 Node.js 24.22.3，Electron 45.5.0、Playwright 1.65.1。此次留存两组数据。

| 实测场景 | 样本与结果 |
| --- | --- |
| 拉起应用至文件中心可打开文件 | 启动六个相继退出的进程，每轮使用独立临时用户目录及同一初始工作区。首轮 591 ms 作为预热；后五轮 536、561、584、549、564 ms，中位 561 ms。 |
| 从工作区打开已有 Markdown 笔记 | 同上，从点击已载入工作区的测试页，到正文编辑器可见且全文末尾标记可读，15,254 字符、161 段、44,382 UTF-8 字节。后五轮 129、137、134、145、124 ms，中位 134 ms。文件中心从磁盘读取并解码外部 MD 的耗时需另测。 |
| Markdown 打开 1 秒后的应用进程树 | 五轮私有内存合计 256、253、259、252、257 MiB，中位 256 MiB。使用 Electron 进程列表的 `memory.privateBytes` 累加再除以 1024。[Electron 内存字段](https://www.electronjs.org/docs/latest/api/structures/memory-info) |
| 2,000 个行公式加汇总，重新建立计算器 | A1…A2000 存行号，B 列逐行乘 2，C1 对整个 B 列求和。每轮新建 evaluator 并读取 C1，结果均为 4,002,000。预热 5 次，记录 30 次，P50 为 5.47 ms、P95 为 8.90 ms、最大 9.27 ms。仅覆盖 Node 中的模型计算。 |

复测桌面数据时，以 `initialWorkspace()` 为底稿，添加一张普通笔记。每段由“段落”、0 起始段号、“。”及重复八次的“离线编辑用于本地写作。”组成。160 段用两个换行隔开，最后另起一段附“结束标记”。将 JSON 写入隔离的 `YANYE_PROFILE`。从调用 Playwright Electron launch 前开始计时，到“打开本地文件”按钮可见结束第一段；随后给页面设离线，从点击该笔记前计时到校验正文末尾结束第二段。进程正常关闭后进行下一轮。[桌面驱动与隔离方式](../test/desktop.mjs) · [工作表计算器](../src/modules/spreadsheet.js)

以上启动观测包含自动化连接开销，系统文件缓存沿用前一轮，背景负载没有锁定。五个样本只用于给出中位数和范围。8 GiB 基础机的系统冷启动、输入到真实呈现、滚动、磁盘写回、PDF/TXT 以及各模块的压力样本仍需按上表补测。
